# 播放链路决策分析：为何跳转观看，以及是否维持现状

> 对象：项目 007 片单站（GitHub Pages + EdgeOne 双端，主页直出 2010 条漫剧/AI 剧）
> 结论：**维持「跳转原站」现状**，补一个跳转中间页 + 前置版权标注；**不做 iframe 嵌入**。
> 依据均为本机实测，非推断。

## 1. 为什么当前设计为「点击卡片 → 新标签跳转原站」

### 1.1 数据源结构：先天就没有播放能力

外部片单的每条记录只有元数据，其中最"接近"视听内容的也只是**封面图片的 CDN 地址**。它不包含：

- 任何剧集粒度的对象（没有 `episodes[]`，只有一个总数 `episodes: 1000`）
- 任何 `sources` 数组、任何 `container` / `quality` / `codec`
- 任何 HLS manifest 或 mp4 直链

对照项目自有内容的 `episodes/*.json`，播放所必需的是 `sources[].url`。**两种数据形状完全不同，2010 条外部数据里没有任何一条具备播放能力。**

这不是"还没做"，而是采集时就刻意止步于此——`index.json` 的 `attribution` 字段已经把边界写死：仅含元数据与来源链接。

### 1.2 版权与合规：跳转与内嵌是两种法律性质

这是最核心的一条。两者在著作权法上的定位完全不同：

| | 跳转链接 | 站内播放 |
|---|---|---|
| 行为性质 | **导航/索引**，用户去了内容权利人的页面 | **提供作品**，你的站点在向用户传输内容流 |
| 是否构成传播 | 不构成，收看发生在原站 | 构成未经授权的信息网络传播 |
| 权利人视角 | 导流，通常是被允许的 | 替代了原站的观看场景，直接损害其商业利益 |

红果免费漫剧的正片著作权归平台与出品方所有，**不存在面向第三方的公开播放/下载 API**。要合法地在站内播放，只有一条路：通过内容的分发 SDK 或开放平台做**签约授权接入**。

而这条路的门槛不是代码，是资质——需要《广播电视节目制作经营许可证》、ICP 备案、网络文化经营许可证、短剧授权书等。个人与小团队项目在当前阶段基本不可达。

### 1.3 robots.txt：原站已经把话说死了

实测 `hongguoduanju.com/robots.txt`，对 `User-agent: *` 明写：

```
Disallow: /player/*/*
Disallow: /series/
```

这意味着：**播放器和 `/series/` 路径，原站明确不接受自动化访问。**

同时注意 `/detail` **没有被 disallow** —— 卡片链接的正是 `/detail?series_id=xxx`。也就是说，当前的跳转设计恰好落在原站允许的访问面上，而任何试图取出播放地址的动作，第一步就踏进了被禁止的路径。

这一点在争议中的杀伤力远大于著作权模糊地带：可以直接被举证为"明知对方拒绝，仍爬取"。

### 1.4 原站技术防护：SSR + 时效签名，且你的两端都没有续签能力

- 详情页是**火山引擎 DCDN + SSR 渲染**（`Server: volc-dcdn`、`X-Modernjs-Render: server`）。真实片源地址由前端在运行时带签名换取，不是页面里的静态 URL。
- 这类地址普遍带时效性签名、Referer 校验与会话态绑定。即便某次侥幸解析出来，生命周期通常是分钟到小时级。
- **你的两个托管端都不具备实时续签能力**：GitHub Pages 纯静态；EdgeOne 当前也是 `static/` + 少量 cloud-functions 的形态，没有稳定维持登录态或签名的运行环境。

结果很确定：**就算抓到了，也是"今天能播、明天全挂"**。

### 1.5 维护成本：这是无底洞

按 2010 部 × 每部数百集的量级，要维持站内播放意味着：

- 持续逆向/跟随播放接口 —— 上游一次改版，全站播放能力瞬间归零
- 处理签名过期、地域限制、频率限制、付费集判断
- **承担全部视频出口流量**：流量从原站 CDN 转移到你的 EdgeOne / GitHub Pages
- GitHub Pages 有软带宽限制，视频级别流量极易触发滥用判定，风险是整站被封

这不是一个"做完就完了"的功能，是一份随时可能被清零的全职运维工作。

## 2. 站内播放方案评估

### 方案 A · 嵌入官方播放器 SDK

| 维度 | 评价 |
|---|---|
| 技术可行性 | 高，官方 SDK 稳定可靠 |
| 合规风险 | **无**，这是唯一完全合法的站内播放路径 |
| 实际门槛 | **企业资质 + 商务签约**（经营许可证、ICP、文网文、授权书） |
| 结论 | 方向上正确，当前项目阶段不可达。**列为长期选项** |

### 方案 B · iframe 嵌入原站 ❌ 不建议

实测的一个反直觉结果：详情页**没有** `X-Frame-Options`，也**没有** CSP `frame-ancestors`。所以浏览器在 header 层面不会拦截，很可能在技术上"能嵌进去"。

但**能嵌 ≠ 该嵌**，理由四条：

1. **robots 依旧禁止** `/series/` 与 `/player/*/*`。iframe 绕过了 header 限制，但没有绕开站点已经公开声明的接入规则。
2. **SSR 页面随时可能加 frame-buster**。这种页面自带防嵌套脚本的成本极低，上游某次发版加一段，你的整页立刻白屏，而且不可预知、不可防御。
3. **商业性质最恶劣**。把别人的播放器框在自己的域名下播放自家内容，属于用他人版权内容填充自己站点，法律风险显著高于跳转——跳转至少是"导流"，iframe 是"占用"。
4. **移动端体验不成立**。竖版短剧的全屏切换、进度保持、付费弹窗在跨域 iframe 里基本都无法正常工作。

> 一句话：**技术上最容易，合规上最危险。这是本次评估里唯一明确排除的选项。**

### 方案 C · 跳转中间提示页 ✅ 推荐做

点击卡片后先进站内一个轻量页面：封面 + 标题 + 集数 + 来源标注 + 免责说明 + 「前往红果观看」按钮，二次确认后才跳走。

- **法律性质不变**：依然是导航跳转，不构成传播
- **解决两个真实痛点**：① 用户现在不知道自己会被弹到站外；② attribution 目前只在首页底部一行小字，信息暴露严重不足
- **顺带收益**：可以统一控制 `rel="noopener"` 与 `referrerpolicy`，还能在本地存「看过」标记做打点（纯本地，不碰视频）
- **面向未来**：它同时是自有内容的天然落点——某部剧一旦有了自有的 `sources`，同一路由直接渲染成本地播放页，用户无感升级
- **成本**：纯静态改动，低
- **风险**：无新增。唯一注意是**不要把它做成伪装成本站播放器的外壳**，那会改变法律性质

### 方案 D · 双轨并行（中长期形态）

- **发现层**：保留 2010 条跳转片单，它的价值是「让用户找到剧」，不是「让剧在这里播」
- **播放层**：用项目已有的 AI 生成能力 + CC0 素材管道生产**自有内容**，走已验证的 `/internal` 源 + `hls.js` 播放器

这条路的地已经铺好了——`index.html` 里 `startPlayback()` / `fallback()` / hls.js 的完整链路都在，还带着优雅降级（`"该剧集没有浏览器可播放的片源"`）。缺的只是内容本身，且完全符合 `docs/漫剧资源获取与集成方案.md` 里的 A 类推荐方向。

## 3. 建议

### 结论：维持跳转现状，做三处小改

| 优先级 | 改动 | 收益 |
|---|---|---|
| P0 | **跳转中间提示页**（方案 C） | 合规信息前置 + 体验明确，零法律风险 |
| P0 | attribution 从首页小字提到**卡片/详情页可见位置**；补充 `rel="noopener"` 与 `referrerpolicy` | 版权留痕到位 |
| P1 | 明确站点定位为**片单索引与发现**，不与播放混为一谈 | 长期降低被认定侵权替代的概率 |
| P2 | 启动方案 D，产出自有 CC0/AI 内容，把已铺好的播放器链路用起来 | 真正实现站内播放，且完全合规 |

### 不要做的事

- ❌ iframe 嵌入原站详情页
- ❌ 解析 `/player/*/*` 或任何逆向播放接口取 m3u8
- ❌ 服务端代理转发片源流量（也会违反 `server/app/services/sources/user_defined.py` 已立的白名单红线）

### 一句话

> 现在这套设计不是"技术上的妥协"，而是**在给定数据源、合规边界与运维成本下唯一站得住的方案**。真正想要站内播放，正确的解法不是去破解别人的播放地址，而是用自有内容把它填上——那条管道你已经有了。

## 4. 落地情况（2026-09-25 已实施）

### 4.1 P0 · 跳转中间提示页 ✅ 已实现

新增路由 `#/ext/{category}/{id}`，改动均在 `makers/static/index.html`：

- 卡片不再直跳。`extCardHtml()` 由输出 `data-url` 改为输出 `data-cat` + `data-id`，卡片左上角新增**来源角标**（`source_label`）。
- 点击卡片进入提示页而非弹窗，`viewExtGate()` 渲染：封面、标题、来源平台、分类、集数 + 「前往 XX 观看」按钮 + 「返回列表」。
- 提示页底部 `notice` 区块明确声明：本站不存储、不转码、不代理视频，并展示 `index.json.attribution` 与即将前往的完整 URL。
- 未知 id 走「未找到该条目」优雅兜底。
- **保留了播放 LOC 的法律性质**：行为仍是用户二次确认后的导航跳转，没有任何伪播放器外壳。

### 4.2 P0 · 版权标注前置 + 链接安全属性 ✅ 已实现

- `external/index.json` 里的 `attribution` 此前只在首页一行小字出现，现已在**分类页、列表页、跳转提示页**三处前置展示（`.notice` 醒目区块）。
- 跳转链接为真实 `<a>` 元素，携带：
  - `target="_blank"` `rel="noopener external"`
  - `referrerpolicy="strict-origin-when-cross-origin"`

> 关于为何**不用** `noreferrer`：`noreferrer` 会抹掉 Referer，使原站看不到流量来源。本站的性质是**导流**，让原站能看到来源反而有利于证明这一点。`strict-origin-when-cross-origin` 是浏览器默认行为，跨源时只发送 origin，不泄露具体页面路径，兼顾了隐私与可溯源性。

### 4.3 顺带实现 · 「已看过」标记

进入提示页时把条目 id 写入 `localStorage`（键 `manju:ext:seen`，上限 500 条），列表卡片显示「已看过」角标。**只存 id，不触碰任何视频内容**，隐私模式下静默失败不影响主流程。

### 4.4 回归验证

| 验证项 | 结果 |
|---|---|
| 新增 `makers/scripts/smoke_web.mjs`（极简 DOM stub 上实跑内联脚本） | **10/10 通过** |
| 既有 `makers/scripts/smoke.mjs`（服务端契约） | **16/16 通过**，无回归 |
| 本地 `python -m http.server` 静态路径 | **10/10 返回 200** |
| 全文件 `window.open` 直跳残留 | **0 处** |

### 4.5 未实施项（需额外资源或决策）

- **P2 自有内容生产**（方案 D）：需要实际调用 ImageGen / VideoGen 生成漫画帧与动态片段，再经 `scripts/acquire_assets.py` + `seed_content_library.py` 入库。播放器链路（`startPlayback()` / `fallback()` / `js/hls.min.js`）已就绪，缺的是内容本身——这需要单独的生成任务，不在本次范围内。
- **方案 A 官方播放器 SDK**：受限于企业资质，仍为长期选项。
