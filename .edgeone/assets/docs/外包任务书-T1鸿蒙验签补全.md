### 任务名称
【项目007·漫剧 Manju】鸿蒙端 OTA 更新包 SHA256 / Ed25519 验签补全（双侧）

### 背景（限 200 字）
漫剧 Manju 是覆盖六端的短剧客户端，已实现 OTA 更新协议 v1（完整定义见仓库 `spec/ota-protocol.v1.md`）。
协议要求客户端在下载更新包后**必须**校验 `sha256`，生产环境**必须**校验 Ed25519 签名（公钥编译进客户端）。
当前 Flutter / RN / Tauri 三端已实现验签，**鸿蒙端两个实现均缺失**：
- RN harmony 侧：仅有签名字段声明，无任何校验实现
- Flutter ohos 侧：连字段声明都没有

因鸿蒙平台限制（禁止侧载静默安装），鸿蒙端只能跳转应用市场，
风险限于**跳转 URL 被篡改**，目前已由 HTTPS 缓解；但仍需按协议补齐校验。

### 你的交付范围（共 2 个文件，缺一不可）
1. `clients/manju_rn/harmony/entry/src/main/ets/updater/Updater.ets`
   —— 当前第 36 行仅有 `signature?: string` 字段声明，需补**可执行的** SHA256 校验
2. `clients/manju_flutter/ohos/entry/src/main/ets/updater/UpdaterPlugin.ets`
   —— 当前全文无 `sha256` / `verify` / `crypto` 任何相关代码，需**从零补齐**

两个文件均需按同一份协议实现，行为保持一致。

### 实现要求（逐条）
1. **SHA256 校验**：下载完成后对文件字节流计算 SHA256，与协议 `artifact.sha256` 比对；
   **不匹配立即中止并上报事件**，不得继续安装或跳转
2. **Ed25519 验签**：
   - 首选：用 `cryptoFramework` 验签协议中的 `artifact.signature`（形如 `ed25519:MEUCIQDx...`）
   - **若 `cryptoFramework` 不支持 Ed25519**：不得静默跳过，
     须**书面说明**不支持的证据（官方文档/实测报错），并实现明确的降级分支：
     仅 SHA256 + 仅允许 HTTPS 源 + 日志告警，同时在代码注释与交付文档中标注风险
3. **规范化消息**：签名对象是协议定义的**规范化消息**（不是文件字节），
   具体拼接规则以 `spec/ota-protocol.v1.md` 为准；如文档未明确，向我方确认，**不得自行假设**
4. **失败行为**：校验失败 → 中止 → 上报 `event`（与现有 `UpdaterPlugin.ets` 中
   `reportEvent(..., 'unsupported', 'platform_restricted')` 的报告机制保持一致）
5. 鸿蒙平台红线：无论如何**不得**实现任何静默安装/侧载逻辑，只能跳转应用市场
