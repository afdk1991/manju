## 一、边界划分（总原则）

### ✅ 自己做（绝不外包）
核心业务逻辑、架构设计、`spec/openapi.yaml` 契约与 `spec/ota-protocol.v1.md`、数据库设计、
OTA 服务端、版本主控、发布权限。

### 📤 可外包
UI/UX 设计、纯展示页面、通用组件、**平台特定补全（如鸿蒙验签）**、测试与众测、
安全扫描、合规文档、上架素材、运维脚本、非核心 CRUD。

### ❌ 绝不外包（红线，违反即终止）
| 资产 | 说明 |
|---|---|
| `keys/` 下的 Ed25519 OTA 私钥 | 历史上曾误推 GitHub（已轮换 + 清史），**绝不可再外传** |
| `manju-release.keystore` | 一旦换密钥 = 新应用，用户必须卸载重装 |
| Apple Developer 证书 / `.p12` / `.p8` | 账号主体资产 |
| 各平台开发者账号与上架权限 | 只能自己持有，外包只给"上传员"子账号 |
| `server/data/manju.db` 内容数据源 | 内容主权 |
| 服务器 SSH / 数据库账号 / 发布 Token | 只给临时、可回收的最小权限 |

## 四、验收标准模板（通用，逐项勾选）

### 4.1 代码类任务
- [ ] 通过对应静态检查，退出码 0（附命令与输出截图）
- [ ] 未改动 `spec/` 契约文件（diff 中不得出现）
- [ ] 未引入未经批准的第三方依赖（附 `pubspec.yaml` / `package.json` / `oh-package.json5` diff）
- [ ] 无硬编码密钥、Token、内网地址
- [ ] 提交为 PR，非直接推主干
- [ ] 附可复现自测步骤

### 4.2 设计类任务
- [ ] 源文件齐全（Figma / Sketch / PSD 分层）
- [ ] 三端适配（移动 / 桌面 / 平板）
- [ ] 切图尺寸与命名符合要求（含 @2x/@3x）
- [ ] Mac App Store 场景需 ICNS 含 1024×1024 条目

### 4.3 测试类任务
- [ ] 机型/系统覆盖表齐全（Android 主流 + iOS + Windows + macOS + 鸿蒙）
- [ ] Bug 清单含：复现步骤、严重度、影响范围、截图/录屏
- [ ] 核心流程无阻塞 Bug；一般 Bug 修复率 ≥95%
- [ ] 播放链路真判据已实测：播放页 `<video src="blob:...">`

### 4.4 合规类任务
- [ ] 隐私政策覆盖：收集项、用途、第三方共享、用户权利
- [ ] 明确内容授权合规声明（所分发内容须已获授权）
- [ ] 无爬取/破解相关内容表述
- [ ] 符合各平台上架规则

## 五、付款与风控

| 项 | 做法 |
|---|---|
| 付款节奏 | **3-3-4**：签约 30% → 中期可演示 30% → 验收通过 40% |
| 质量风险 | 每个任务设明确验收节点；核心代码自己最终把关；**不交付源码控制权**（PR 由我方合入） |
| 进度风险 | 提前排期 + 预留 20% 缓冲；核心环节自己做备份方案 |
| 保密风险 | 签 NDA；核心算法/数据不提供；外包仅开放有限权限（临时账号，验收后回收） |
| 人员断层 | 同一环节备选 2~3 个服务商或个人，避免单一依赖 |
| 成本风险 | 固定预算、按需发包；优先保障 🔴 P0 任务（T1 鸿蒙验签、T4 测试、T5 合规） |
