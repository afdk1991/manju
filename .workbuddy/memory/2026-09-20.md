## makers/ 架构（为什么这样设计）
EdgeOne Makers 的 Cloud Functions **文件系统不可持久化**，所以：
- SQLite 不部署，内容导出为**静态 JSON** 放 `static/api/v1/`，走 CDN 边缘加速
- `edgeone.json` 用 rewrites 把 `/api/v1/xxx` 映射到 `xxx.json`，
  客户端 API 路径与响应结构**完全不变**
- Cloud Functions 负责：OTA check / report、search、admin releases、user favorites/history
- `@edgeone/pages-blob`（免费 1GB）做持久化存储：OTA 上报、收藏、历史、admin 增量发布
- `data/**` 通过 `includeFiles` 打包进函数，供搜索与 OTA 检查读只读索引

**客户端零改动**：只需把 `MANJU_API_BASE` / `API_BASE` 指向部署域名。

## 重要：验证受限
自动化 curl 探测线上接口返回 **401（无 token）** / **302（SSO 登录跳转）**，
这是 EdgeOne Makers 预览部署的鉴权行为，**不代表部署失败**。
必须在**系统浏览器**打开（内置浏览器无法处理 SSO 302）。

## 关键事实：签名是自动安装的前提
| 平台 | 签名 |
|---|---|

| Android | **必须** keystore，换 keystore = 换应用 |
| iOS / 鸿蒙 | **必须** 平台证书 + Profile，只能商店分发 |
| Windows | MSIX 建议签名（免管理员权限，自更新体验最好） |
| Linux | 通常不需要 |

## 关键教训：工程师说"完成"不等于能编译
本轮**亲自跑构建**，抓出两处工程师漏掉的真实问题：

1. **Tauri 端 `npm run build` 19 处 TS 错误**（tauri-finisher 报告"完成"但没跑构建）
   - `useUpdater.ts` 含 JSX 却是 .ts 扩展名 → 已重命名为 .tsx（我修的）
   - `getBuildNumber` 不是 `@tauri-apps/api/app` 的导出
   - `deviceId` 应为 `device_id`（OTA 协议是 snake_case）
   - `downloadAndInstall` 不是 plugin-updater 模块级导出，应先 `check()` 再在 update 对象上调
   - `appCacheDir`/`tempDir` 不是 plugin-os 的导出
   - `@noble/hashes/utils` 没有 `base64` 导出（应为 `bytesToBase64`）
   - 已把这些整理成清单 SendMessage 让 tauri-finisher 返工

2. **RN 端 `npm install` 直接失败**：`react-native@0.74.5` 与
   `@react-native/babel-preset@0.74.5` **版本不存在**；
   `metro-react-native-babel-preset` 已废弃。
   实际最新是 **0.87.1**，且 peer 要求 `react ^19.2.3` / `@types/react ^19.1.1`。
   已改写 package.json（react 19.2.3、navigation 7.x、移除废弃包与 @types/react-native）。
