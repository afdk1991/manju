# 项目007 · 外包发包与脱敏打包

> 对应方案A 第二章（自主开发 & 按需外包边界）与第六章风险管控。
> 关联风险：R-01 外包质量、R-03 保密、R-04 人员断层、R-09 工具链缺口。

## 何时使用

- 要把 T1~T8 任一包发包（清单见 `docs/外包任务说明书与验收标准.md` §2）
- 需要给外包方提供代码片段 / 设计稿 / 环境信息
- 外包交付物到货，需要按验收标准核对

## 发包前六步

1. **定位交付范围**：只写「要改的那个文件 + 那几行」，不写整仓。例：T1 只需
   `clients/manju_rn/harmony/.../updater/Updater.ets` 与 `clients/manju_flutter/ohos/.../updater/UpdaterPlugin.ets`。
2. **脱敏抽取**：用子代理或脚本只拷出目标文件到临时目录，**不拷 `keys/`、`.env`、`.git/`**。
3. **套任务书模板**：复制 `docs/外包任务说明书与验收标准.md` §3 模板，逐段填写
   （背景限 200 字 / 交付范围 / **明确不包括** / 技术约束 / 验收标准逐条可判 / 交付物 / 工期与付款 / 保密）。
4. **保密自检**（见下方命令，必跑）。
5. **签 NDA**：用 `docs/外包合同与NDA模板.md`，签完再给材料。
6. **最小权限授权**：GitHub 只开只读分支或独立 fork，**不开放 Secrets**；验收后立即回收。

## 🔴 红线（违反即终止合作）

| # | 绝不外包 / 绝不外传 |
|---|---|
| 1 | 核心业务算法、核心业务接口、数据库设计、版本主控 |
| 2 | 数据库账号权限、用户核心数据、支付密钥 |
| 3 | `keys/*.pem`（OTA 私钥）、`manju-release.keystore`、Apple 证书、开发者账号 |
| 4 | `.env`、MCP token、GitHub Secret、EdgeOne 环境变量 |
| 5 | 整仓代码 / 完整 git 历史（只给单点文件） |

> 付款节奏统一 **3-3-4**（签约 30% → 中期可演示 30% → 验收通过 40%），逾期按日扣 2%，上限 20%。
> PR **由我方合入**，不交付源码控制权。

## 保密自检命令（发包前必跑）

敏感扫描用宽匹配，**不要在仓库文件里写完整的私钥头字面量**（CI `security-gates` 会命中并让硬门禁变红）：

```bash
# 1. 私钥/证书扫描（宽匹配，等价且不会触发 CI 自扫描）
git grep -nI -E 'BEGIN [A-Z ]*PRIVATE KEY' -- . || echo "OK: 无私钥"

# 2. .env / keystore / pem 是否被误打包
ls -1 <临时交付目录> | grep -iE '\.env|\.pem|\.keystore|\.jks|id_rsa|\.git$' && echo "⛔ 命中敏感文件" || echo "OK"

# 3. 确认 keys/ 未被跟踪
git ls-files keys/ | head -5   # 应为空
```

## 交付物验收

按 `docs/外包任务说明书与验收标准.md` §4 的四类模板（代码 / 设计 / 测试 / 合规）逐项勾选。
对外包提交的任何「跑通」结论，必须索要**具体命令 + 实际输出**（风险台账 R-11 铁律）。

## 备选池

同一环节保持 **2~3 个备选服务商/个人**（R-04）。当前建议优先建 T1 / T4 / T5 三家的备选。
